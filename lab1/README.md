## Теоретическое обоснование

**Композиция** — строгое отношение «часть-целое», при котором объект-часть не может существовать без объекта-целого. Жизненный цикл части полностью контролируется целым. В C++ реализуется через поля-объекты, либо через указатели с ручным выделением/освобождением памяти (или через `std::unique_ptr`).

**Агрегация** — более слабое отношение «часть-целое», при котором части могут существовать независимо от целого. В C++ реализуется через указатели или ссылки, передаваемые извне. Класс-целое не отвечает за удаление этих объектов.

**Статические члены класса** — это поля и методы, принадлежащие самому классу, а не его экземплярам. Используются для ведения общих счётчиков или реализации паттерна Singleton.

**Паттерн «Одиночка» (Singleton)** — гарантирует наличие только одного экземпляра класса и предоставляет глобальную точку доступа к нему (реализуется через приватный конструктор и статический метод).

## Ключевые фрагменты кода

**Singleton (класс Store)**

```cpp
class Store {
    std::string name;
    static Store* instance;          // статическое поле-одиночка
    Store(const std::string& n) : name(n) {}   // закрытый конструктор

public:
    static Store* getInstance() {
        if (!instance) instance = new Store("TechnoMart");
        return instance;
    }
    std::string getName() const { return name; }
};
    Store* Store::instance = nullptr;
```

**Композиция и статический счётчик (класс Purchase)**

```cpp
class Purchase {
    std::string product;
    Store& store;                    // КОМПОЗИЦИЯ: ссылка (не может быть nullptr)
    static int count;                // статический счётчик объектов

public:
    Purchase(const std::string& p, Store& s) : product(p), store(s) {
        ++count;
        std::cout << "Purchase #" << count << ": " << product
                  << " в " << store.getName() << "\n";
    }
    ~Purchase() { --count; }
    static int getCount() { return count; }
};
int Purchase::count = 0;
```

**Агрегация (класс Customer)**

```cpp
class Customer {
    std::string name;
    Store* store = nullptr;          // АГРЕГАЦИЯ: указатель (может быть nullptr)

public:
    Customer(const std::string& n) : name(n) {}
    void setStore(Store* s) { store = s; }

    Purchase* buy(const std::string& p) {
        if (!store) {
            std::cout << name << " не может купить: нет магазина\n";
            return nullptr;
        }
        return new Purchase(p, *store);
    }
};
```

## Контрольные вопросы

1. **Что такое композиция? Приведите пример.**
   Композиция — это отношение, при котором объект-часть не может существовать отдельно от объекта-целого. Пример: Дом и Комната (если снести дом, комнаты исчезнут).

2. **Что такое агрегация? Чем она отличается от композиции?**
   Агрегация — это отношение, при котором часть может существовать независимо от целого. Отличие в управлении жизненным циклом: при композиции целое удаляет части, при агрегации — нет.

3. **Как реализовать композицию в C++? Приведите пример кода.**
   Через поле-объект или через указатель с выделением памяти в конструкторе и `delete` в деструкторе. Пример: `class A { B b; };` или `A() { b = new B(); } ~A() { delete b; }`.

4. **Как реализовать агрегацию в C++? Приведите пример кода.**
   Через указатели или ссылки, передаваемые в класс извне. Деструктор класса-целого не удаляет эти объекты. Пример: `class A { B* b; public: A(B* ptr) : b(ptr) {} };`

5. **В чём разница между временем жизни частей при композиции и агрегации?**
   В композиции время жизни части ограничено целым (создается и удаляется вместе с ним). В агрегации части могут жить дольше целого.

6. **Что такое статическое поле класса? Чем оно отличается от обычного поля?**
   Это поле, принадлежащее всему классу, а не отдельному объекту. Оно существует в единственном экземпляре и является общим для всех объектов.

7. **Как объявить и определить статическое поле? Где оно хранится?**
   Объявляется внутри класса (`static int x;`), определяется вне класса (`int Class::x = 0;`). Хранится в статической области памяти, а не в объекте.

8. **Что такое статический метод? Можно ли из него обратиться к нестатическим полям?**
   Метод, вызываемый без создания объекта. Из него **нельзя** обращаться к нестатическим полям, так как нет указателя `this`.

9. **Для чего используются статические счётчики объектов?**
   Для отслеживания количества существующих объектов класса (увеличивается в конструкторе, уменьшается в деструкторе).

10. **Что такое паттерн «Одиночка» (Singleton)? Для чего он нужен?**
    Гарантирует наличие одного экземпляра класса и предоставляет глобальную точку доступа (например, для базы данных или конфигурации).

11. **Как запретить создание копий объекта?**
    Удалить конструктор копирования и оператор присваивания: `Class(const Class&) = delete;`.

12. **В каком порядке вызываются конструкторы и деструкторы при композиции?**
    Конструкторы частей вызываются до тела конструктора целого. Деструкторы — в обратном порядке (сначала тело деструктора целого, затем части).

13. **Можно ли изменить статическое поле из обычного метода?**
    Да, обычные методы имеют доступ к статическим полям.

14. **Почему статические поля нужно определять вне класса?**
    Внутри класса — это только объявление. Определение вне класса выделяет память для статического поля.

15. **В каких случаях стоит использовать композицию, а в каких - агрегацию?**
    Композиция — когда часть является неотъемлемым атрибутом целого (двигатель и машина). Агрегация — когда объекты связаны логически, но могут существовать автономно (студент и университет).
