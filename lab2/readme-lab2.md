## Теоретическое обоснование

**О-нотация (Big O)** — это математическая запись, описывающая асимптотическое поведение функции (как быстро растет время работы алгоритма при увеличении входных данных), отбрасывая константы и младшие члены.
Основные классы сложности: 
* **O(1)** — константная (доступ к элементу массива по индексу).
* **O(log n)** — логарифмическая (бинарный поиск).
* **O(n)** — линейная (линейный поиск, проход по массиву).
* **O(n log n)** — линейно-логарифмическая (эффективные сортировки).
* **O(n²)** — квадратичная (два вложенных цикла).

**Шаблоны классов** позволяют создавать универсальные структуры данных, тип которых определяется при их использовании (например, `std::vector<T>`). Это избавляет от дублирования кода.

**Разреженный массив (SparseArray)** — структура данных, предназначенная для экономии памяти при хранении массивов, в которых большинство элементов пустуют (равны нулю по умолчанию). Вместо выделения памяти под весь диапазон индексов, хранятся только реально заданные значения.

## Ключевые фрагменты кода

**Шаблонный класс SparseArray (на базе std::map)**

```cpp
#include <iostream>
#include <map>
#include <chrono>
#include <windows.h>

using namespace std;
using namespace std::chrono;

// Класс разреженного массива
template <typename T>
class SparseArray {
private:
    map<int, T> data; // Храним только заполненные индексы (индекс -> значение)

public:
    // Установить значение по индексу
    void set(int index, T value) {
        data[index] = value;
    }

    // Получить значение по индексу (если пусто, вернет 0 или дефолтное значение типа)
    T get(int index) {
        if (data.find(index) != data.end()) {
            return data[index];
        }
        return T(); 
    }

    // Удалить значение по индексу
    void remove(int index) {
        data.erase(index);
    }

    // Вернуть логический размер (максимальный индекс + 1)
    int size() {
        if (data.empty()) return 0;
        return data.rbegin()->first + 1;
    }
};
```

## Анализ сложности операций

Поскольку в основе реализации лежит сбалансированное красно-черное дерево (`std::map`), сложность операций выглядит следующим образом:

| Операция | Сложность | Обоснование |
| :--- | :--- | :--- |
| `set` (запись) | **O(log N)** | Поиск места для вставки в дереве и балансировка. |
| `get` (чтение) | **O(log N)** | Поиск элемента по ключу (индексу) в дереве. |
| `remove` (удаление) | **O(log N)** | Поиск элемента и удаление узла из дерева с балансировкой. |
| `size` | **O(1)** | Получение максимального индекса через обратный итератор (`rbegin()`). |

## Контрольные вопросы

1. **Что такое О-нотация (Big O) и зачем она нужна?**
   Это математическая нотация для описания асимптотической сложности алгоритма. Она нужна для оценки того, как быстро будет расти время выполнения или объем потребляемой памяти при увеличении входных данных, независимо от аппаратного обеспечения.

2. **Какая сложность у доступа к элементу массива по индексу? Почему?**
   O(1) — константная. Потому что в памяти массив хранится непрерывно, и адрес элемента вычисляется математически: `адрес_начала + индекс * размер_типа`. Это требует одинакового количества операций для любого индекса.

3. **Какая сложность у бинарного поиска? Почему?**
   O(log n). На каждом шаге алгоритм делит область поиска пополам. Количество шагов равно степени, в которую нужно возвести 2, чтобы получить n.

4. **Что означает сложность O(n log n)? Приведите пример алгоритма.**
   Это линейно-логарифмическая сложность. Означает, что алгоритм выполняет n операций, каждая из которых занимает log n времени. Пример: быстрая сортировка (QuickSort) или сортировка слиянием (MergeSort).

5. **Что такое амортизированный анализ? Приведите пример.**
   Это метод оценки, который усредняет стоимость операции в худшем случае по всей последовательности операций. Пример: добавление элемента в `std::vector`. Обычно это O(1), но при переполнении выделяется новая память и копируются все элементы (O(n)). Однако в пересчете на все добавления средняя стоимость (амортизированная) остается O(1).

6. **Какая сложность у двух вложенных циклов по n итераций каждый?**
   O(n²) — квадратичная сложность (если циклы не зависят друг от друга).

7. **Какая сложность у рекурсивного вычисления чисел Фибоначчи?**
   O(2^n) — экспоненциальная сложность (при наивной реализации без мемоизации), так как каждый вызов порождает два новых.

8. **Что такое шаблоны функций? Как их объявить и использовать?**
   Это механизм C++, позволяющий писать функции, работающие с разными типами данных. Объявление: `template <typename T> T func(T a) { ... }`. Использование: `func<int>(5)` или автоматически `func(5)`.

9. **Что такое шаблоны классов? Как их объявить и использовать?**
   Это механизм для создания универсальных классов. Объявление: `template <typename T> class MyClass { ... };`. Использование: `MyClass<int> obj;`.

10. **В чём преимущество шаблонов перед перегрузкой функций?**
    Шаблоны позволяют избежать дублирования кода. Вместо написания десятка перегрузок для разных типов (int, double, float), вы пишете один шаблон, и компилятор сам генерирует нужные версии функций.

11. **Как указать, что шаблонный параметр - тип?**
    С помощью ключевого слова `typename` или `class` внутри угловых скобок: `template <typename T>`.

12. **Можно ли создать шаблон с несколькими параметрами типов?**
    Да. Пример: `template <typename T1, typename T2> class Pair { ... };`.

13. **Как провести экспериментальное измерение времени выполнения?**
    С помощью библиотеки `<chrono>`. Засечь время до операции (`high_resolution_clock::now()`), выполнить операцию и засечь время после. Разница между ними покажет время выполнения.

14. **Почему при измерении времени нужно выполнять операцию многократно?**
    Потому что современные процессоры слишком быстрые. Одиночная операция может занять наносекунды, и точность таймера системы может быть недостаточной для корректного замера (погрешность измерения будет больше самого времени). Многократное выполнение позволяет усреднить результат.

15. **Что важнее: сложность алгоритма или константа?**
    Для больших объемов данных (асимптотика) важнее сложность (Big O). Однако для малых массивов алгоритм с худшей сложностью, но меньшей константой (например, сортировка вставками) может работать быстрее, чем сложный алгоритм (например, быстрая сортировка).
