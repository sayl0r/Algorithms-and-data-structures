## Цель работы

Реализовать алгоритм двоичного (бинарного) поиска в отсортированном массиве, освоить методы разрешения коллизий в хеш-таблицах (на примере линейного пробирования), а также сравнить производительность двоичного поиска и хеш-таблицы.

## Теоретическое обоснование

**Двоичный поиск** — алгоритм поиска в отсортированном массиве, который на каждом шаге делит интервал поиска пополам. Сложность O(log n).
**Хеш-таблица** — структура данных для реализации ассоциативного массива. В среднем операции вставки, поиска и удаления выполняются за O(1), в худшем — за O(n).
**Линейное пробирование** — метод разрешения коллизий (открытая адресация), при котором при занятости ячейки поиск следующей свободной происходит с шагом 1: `(hash + i) % size`.

## Постановка задачи (Вариант 12)

1.  **Двоичный поиск:** Реализовать поиск с подсчётом количества вхождений элемента (int).
2.  **Хеш-таблица:** Реализовать таблицу с линейным пробированием. Ключ — `int`, значение — `struct Student`.
3.  **Анализ:** Сравнить производительность бинарного поиска и хеш-таблицы.

## Листинг программы

```cpp
#include <iostream>
#include <vector>
#include <string>

using namespace std;

// ДВОИЧНЫЙ ПОИСК (Подсчёт вхождений)
int countOccurrences(const vector<int>& arr, int target) {
    int left = 0, right = arr.size() - 1;
    int first = -1, last = -1;

    // Ищем первое вхождение
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (arr[mid] == target) { first = mid; right = mid - 1; }
        else if (arr[mid] < target) left = mid + 1;
        else right = mid - 1;
    }
    if (first == -1) return 0; // Не найдено

    // Ищем последнее вхождение
    left = 0; right = arr.size() - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (arr[mid] == target) { last = mid; left = mid + 1; }
        else if (arr[mid] < target) left = mid + 1;
        else right = mid - 1;
    }
    return last - first + 1;
}

// ХЕШ-ТАБЛИЦА (Линейное пробирование, Student)
struct Student {
    string name;
    int age;
};

class HashTable {
private:
    struct Entry {
        int key;
        Student value;
        bool occupied = false;
    };
    vector<Entry> table;
    int size;

    int hash(int key) { return key % size; }

public:
    HashTable(int s) : size(s), table(s) {}

    void insert(int key, Student val) {
        int index = hash(key);
        int i = 0;
        while (table[(index + i) % size].occupied) {
            if (table[(index + i) % size].key == key) { // Обновление
                table[(index + i) % size].value = val;
                return;
            }
            i++;
        }
        int pos = (index + i) % size;
        table[pos] = {key, val, true};
    }

    Student* find(int key) {
        int index = hash(key);
        int i = 0;
        while (table[(index + i) % size].occupied) {
            int pos = (index + i) % size;
            if (table[pos].key == key) return &table[pos].value;
            i++;
        }
        return nullptr;
    }
};

int main() {
    cout << "--- PART 1: Binary Search (Count Occurrences) ---\n";
    vector<int> sortedArr = {1, 2, 2, 2, 3, 4, 5, 5, 6};
    int target = 2;
    cout << "Array: 1, 2, 2, 2, 3, 4, 5, 5, 6\n";
    cout << "Count of " << target << ": " << countOccurrences(sortedArr, target) << "\n\n";

    cout << "--- PART 2: Hash Table (Linear Probing, Student) ---\n";
    HashTable ht(5);
    ht.insert(101, {"Ivan", 19});
    ht.insert(102, {"Maria", 20});
    ht.insert(106, {"Petr", 21}); // Коллизия с 101 (106 % 5 == 1, 101 % 5 == 1)
    
    Student* s = ht.find(106);
    if (s) cout << "Found ID 106: " << s->name << ", Age: " << s->age << "\n";
    
    if (ht.find(999) == nullptr) cout << "ID 999 not found (correct)\n\n";

    cout << "--- PART 3: Comparative Analysis ---\n";
    cout << "Binary Search: O(log N)\n";
    cout << "Hash Table:    O(1) average, O(N) worst\n";

    return 0;
}
```

## Сравнительный анализ

| Алгоритм / Структура | Поиск (средний) | Поиск (худший) | Память | Особенности |
| :--- | :--- | :--- | :--- | :--- |
| **Двоичный поиск** | O(log n) | O(log n) | O(1) | Требует отсортированный массив. |
| **Хеш-таблица (линейное пробирование)** | O(1) | O(n) | O(n) | Не требует сортировки. Возможна кластеризация (слипание занятых ячеек). |

**Вывод:** Хеш-таблица быстрее в среднем (O(1) против O(log n)), но требует больше памяти и может деградировать при сильном заполнении (из-за кластеризации). Двоичный поиск стабилен и предсказуем, но требует предварительной сортировки.

## Контрольные вопросы

1. **Что такое двоичный поиск и каковы его требования к данным?**
   Алгоритм поиска, делящий интервал пополам. Требует, чтобы массив был отсортирован.

2. **Какова сложность двоичного поиска в лучшем, среднем и худшем случае?**
   Лучший: O(1) (если элемент в середине). Средний и худший: O(log n).

3. **В чём разница между итеративной и рекурсивной реализациями двоичного поиска?**
   Итеративная использует цикл (память O(1)). Рекурсивная использует стек вызовов (память O(log n)).

4. **Почему `mid = left + (right - left) / 2` лучше, чем `mid = (left + right) / 2`?**
   Потому что вторая формула может вызвать переполнение типа (integer overflow) при больших значениях `left` и `right`.

5. **Что такое хеш-таблица и для чего она используется?**
   Структура данных для хранения пар «ключ-значение». Используется для быстрого поиска, вставки и удаления данных.

6. **Что такое хеш-функция? Каким требованиям она должна удовлетворять?**
   Функция, превращающая ключ в индекс массива. Требования: детерминированность, равномерное распределение, быстрота вычисления.

7. **Что такое коллизия в хеш-таблице?**
   Ситуация, когда два разных ключа после хеширования дают одинаковый индекс.

8. **Какие методы разрешения коллизий существуют?**
   Метод цепочек (Chaining) и открытая адресация (линейное, квадратичное пробирование, двойное хеширование).

9. **В чём суть метода цепочек?**
   Каждая ячейка таблицы содержит связный список. При коллизии новый элемент добавляется в этот список.

10. **В чём суть линейного пробирования?**
    При занятости ячейки поиск следующей свободной происходит последовательно с шагом 1.

11. **Что такое кластеризация (слипание) при линейном пробировании?**
    Образование длинных последовательностей занятых ячеек, что увеличивает время поиска.

12. **Какая сложность операций в хеш-таблице в среднем и худшем случае?**
    Средний: O(1). Худший: O(n) (когда все элементы попали в одну ячейку или таблица переполнена).

13. **Что такое коэффициент заполнения (load factor) хеш-таблицы?**
    Отношение количества элементов к размеру таблицы. Если он высок, производительность падает.

14. **Зачем нужно динамическое расширение (rehashing) хеш-таблицы?**
    Чтобы поддерживать низкий коэффициент заполнения и сохранять высокую скорость операций O(1).

15. **Что быстрее: двоичный поиск или поиск в хеш-таблице?**
    Хеш-таблица (O(1) в среднем) быстрее двоичного поиска (O(log n)), но при условии хорошей хеш-функции и отсутствия сильного переполнения.
