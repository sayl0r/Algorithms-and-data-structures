## Цель работы

Реализовать три эффективных алгоритма сортировки (быструю, слиянием и пирамидальную), освоить принципы «разделяй и властвуй», изучить структуру данных «куча», а также проанализировать и сравнить производительность различных алгоритмов сортировки, включая специфику распределенных систем.

## Теоретическое обоснование

**Быстрая сортировка (Quick Sort)** использует стратегию «разделяй и властвуй». Выбирается опорный элемент (pivot), относительно которого массив делится на две части: меньше pivot и больше pivot. Затем части сортируются рекурсивно. В среднем работает за O(n log n), но в худшем случае может деградировать до O(n²).

**Сортировка слиянием (Merge Sort)** также делит массив пополам, рекурсивно сортирует каждую половину, а затем сливает их в один отсортированный массив. Всегда гарантирует O(n log n), стабильна, но требует O(n) дополнительной памяти.

**Пирамидальная сортировка (Heap Sort)** использует структуру данных «двоичная куча» (max-heap). Сначала массив превращается в кучу, затем максимальный элемент (корень) меняется местами с последним, и куча восстанавливается. Работает за O(n log n) и не требует дополнительной памяти.

## Ключевые фрагменты кода

**1. Быстрая сортировка (Quick Sort):**
```cpp
void quickSort(vector<int>& arr, int low, int high) {
    if (low < high) {
        int pivot = arr[high];
        int i = low - 1;
        for (int j = low; j < high; ++j) {
            if (arr[j] <= pivot) swap(arr[++i], arr[j]);
        }
        swap(arr[i + 1], arr[high]);
        int pi = i + 1;
        quickSort(arr, low, pi - 1);
        quickSort(arr, pi + 1, high);
    }
}
```

**2. Пирамидальная сортировка (Heap Sort):**
```cpp
void heapify(vector<int>& arr, int n, int i) {
    int largest = i, left = 2 * i + 1, right = 2 * i + 2;
    if (left < n && arr[left] > arr[largest]) largest = left;
    if (right < n && arr[right] > arr[largest]) largest = right;
    if (largest != i) {
        swap(arr[i], arr[largest]);
        heapify(arr, n, largest);
    }
}

void heapSort(vector<int>& arr) {
    int n = arr.size();
    for (int i = n / 2 - 1; i >= 0; --i) heapify(arr, n, i);
    for (int i = n - 1; i > 0; --i) {
        swap(arr[0], arr[i]);
        heapify(arr, i, 0);
    }
}
```

**3. Распределенная сортировка слиянием (MapReduce - Вариант 12):**
```cpp
vector<int> distributedMerge(const vector<vector<int>>& nodes) {
    if (nodes.empty()) return {};
    vector<int> result = nodes[0];
    for (size_t i = 1; i < nodes.size(); ++i) {
        vector<int> temp;
        temp.reserve(result.size() + nodes[i].size());
        std::merge(result.begin(), result.end(), nodes[i].begin(), nodes[i].end(), back_inserter(temp));
        result = move(temp);
    }
    return result;
}

// В main():
```

## Сравнительный анализ

| Алгоритм | Лучший случай | Средний случай | Худший случай | Память | Стабильность |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Quick Sort** | O(n log n) | O(n log n) | O(n²) | O(log n) | Нет |
| **Merge Sort** | O(n log n) | O(n log n) | O(n log n) | O(n) | Да |
| **Heap Sort** | O(n log n) | O(n log n) | O(n log n) | O(1) | Нет |

**Вывод по производительности:** На практике для обычных массивов в памяти Quick Sort обычно быстрее всех благодаря хорошей локальности кэша. Однако для работы с большими данными в распределенных системах (задание варианта 12) Merge Sort является безальтернативным лидером: он позволяет параллельно сортировать независимые блоки данных на разных узлах (фаза Map), а затем просто и эффективно их сливать (фаза Reduce).

## Контрольные вопросы

1. **Какова сложность быстрой сортировки в лучшем, среднем и худшем случае?**
   Лучший и средний: O(n log n). Худший: O(n²).

2. **Когда возникает худший случай для быстрой сортировки?**
   Когда опорный элемент (pivot) каждый раз оказывается минимальным или максимальным в подмассиве (например, при сортировке уже отсортированного массива и выборе крайнего элемента).

3. **Как можно улучшить быструю сортировку для защиты от худшего случая?**
   Использовать рандомизированный выбор опорного элемента или метод «медианы трех» (выбор медианы из первого, среднего и последнего элементов).

4. **Какова сложность сортировки слиянием? Почему она всегда O(n log n)?**
   O(n log n) во всех случаях. Массив всегда делится ровно пополам (log n уровней), и на каждом уровне происходит слияние всех n элементов.

5. **Какие преимущества и недостатки имеет сортировка слиянием перед быстрой?**
   Преимущества: стабильность, гарантированное время O(n log n), идеально для связанных списков и внешней сортировки. Недостатки: требует O(n) дополнительной памяти, на практике чуть медленнее Quick Sort на массивах.

6. **Как работает пирамидальная сортировка? Какова её сложность?**
   Строится max-куча, затем максимальный элемент (корень) меняется местами с последним, куча уменьшается на 1 и свойство восстанавливается. Сложность O(n log n).

7. **Какая из трёх сортировок устойчивая? Почему?**
   Merge Sort. Она сохраняет относительный порядок равных элементов, так как при слиянии мы берем элемент из левой части, если он меньше или равен элементу из правой.

8. **Какая из трёх сортировок требует дополнительной памяти? Сколько?**
   Merge Sort. Требует O(n) памяти для временных массивов при слиянии.

9. **Какая из трёх сортировок лучше работает на почти отсортированных данных?**
   Quick Sort (если правильно выбран pivot) или Merge Sort. Heap Sort на почти отсортированных данных работает так же, как и на случайных.

10. **Зачем в пирамидальной сортировке сначала строится куча?**
    Чтобы корневой элемент всегда был максимальным, что позволяет за O(1) находить следующий элемент для помещения в отсортированную часть.

11. **Что такое «разделяй и властвуй»? Как он применяется в быстрой сортировке и сортировке слиянием?**
    Разбиение задачи на подзадачи, решение их независимо и объединение результатов. В Quick Sort делим массив относительно pivot, в Merge Sort — делим пополам.

12. **Можно ли реализовать быструю сортировку итеративно (без рекурсии)?**
    Да, используя явный стек для хранения границ подмассивов (low и high).

13. **Почему быстрая сортировка обычно быстрее сортировки слиянием на практике?**
    Из-за лучшей локальности кэша (работает в пределах одного массива, не выделяет новую память) и меньшего количества пересылок данных.

14. **Когда выгодно использовать пирамидальную сортировку?**
    Когда критичен объем потребляемой памяти (например, встроенные системы), так как она работает in-place (O(1) доп. памяти) и гарантирует O(n log n).

15. **Какой алгоритм сортировки вы бы выбрали для встроенных систем с ограниченной памятью?**
    Heap Sort, так как он не требует дополнительной памяти (в отличие от Merge) и не уходит в O(n²) в худшем случае (в отличие от Quick).
