## Теоретическое обоснование

**Динамический массив** — структура данных, хранящая элементы в непрерывной области памяти (в куче). В отличие от статического, его размер может изменяться во время выполнения программы. При переполнении память перевыделяется (обычно с удвоением ёмкости), чтобы обеспечить амортизированную сложность добавления O(1).

**Правило пяти** — если класс управляет ресурсами (например, динамической памятью), он должен явно определить 5 методов: деструктор, конструктор копирования, конструктор перемещения, оператор копирующего и оператор перемещающего присваивания.

**Ленивое копирование (Copy-on-Write)** — паттерн оптимизации, при котором объекты при копировании не дублируются в памяти физически. Вместо этого несколько объектов разделяют одни и те же данные (через `std::shared_ptr`). Как только один из объектов пытается изменить данные, создается их полная копия (данные «отделяются»).

## Ключевые фрагменты кода

**Реализация механизма Copy-on-Write и «Правила пяти»:**

```cpp
#include <iostream>
#include <memory>
#include <vector>

template <typename T>
class Vector {
    std::shared_ptr<std::vector<T>> data_;

    // Отделение данных перед изменением (сердце COW)
    void detach() {
        if (data_.use_count() > 1) {
            data_ = std::make_shared<std::vector<T>>(*data_);
        }
    }

public:
    // --- Правило пяти ---
    Vector() : data_(std::make_shared<std::vector<T>>()) {}
    
    // Конструктор копирования (ленивое копирование, O(1))
    Vector(const Vector& other) : data_(other.data_) {} 
    
    Vector(Vector&& other) noexcept : data_(std::move(other.data_)) {}
    
    Vector& operator=(const Vector& other) {
        if (this != &other) data_ = other.data_;
        return *this;
    }
    
    Vector& operator=(Vector&& other) noexcept {
        if (this != &other) data_ = std::move(other.data_);
        return *this;
    }
    
    ~Vector() = default;

    // --- Методы ---
    void push_back(const T& val) { 
        detach(); 
        data_->push_back(val); 
    }
    
    size_t size() const { return data_->size(); }

    // --- Итераторы ---
    // Неконстантные вызывают detach, так как могут изменить данные
    typename std::vector<T>::iterator begin() { detach(); return data_->begin(); }
    typename std::vector<T>::iterator end() { detach(); return data_->end(); }
    
    // Константные только читают
    typename std::vector<T>::const_iterator begin() const { return data_->begin(); }
    typename std::vector<T>::const_iterator end() const { return data_->end(); }
};
```

**Демонстрация работы (main):**

```cpp
int main() {
    Vector<int> v1;
    v1.push_back(1); // Создаем элемент
    
    Vector<int> v2 = v1; // Копирование (COW). Счетчик ссылок = 2.
    v2.push_back(2);     // Модификация v2 вызовет detach(). v2 создаст свой буфер.

    std::cout << "v1: ";
    for (auto it = v1.begin(); it != v1.end(); ++it) std::cout << *it << " ";
    
    std::cout << "\nv2: ";
    for (int x : v2) std::cout << x << " ";
    
    return 0;
}
```

## Контрольные вопросы

1. **Почему динамический массив называется «динамическим»?**
   Потому что его размер определяется и изменяется во время выполнения программы (в куче), а не на этапе компиляции (как у статических массивов на стеке).

2. **Что такое ёмкость (capacity) и чем она отличается от размера (size)?**
   `size` — количество элементов, реально находящихся в массиве. `capacity` — объем выделенной памяти, достаточный для хранения `capacity` элементов без перевыделения.

3. **Почему при расширении массива ёмкость удваивается, а не увеличивается на фиксированное число?**
   Удвоение обеспечивает амортизированную сложность O(1) для `push_back`. Если увеличивать на константу (например, +1), то перевыделение памяти будет происходить на каждой вставке, что приведет к сложности O(N) на операцию.

4. **Какова амортизированная сложность операции push_back? Почему?**
   O(1). Благодаря стратегии удвоения, редкие дорогие операции (O(N)) при расширении «размазываются» по множеству дешевых операций (O(1)), в среднем давая константное время.

5. **Что такое «правило трёх»? Когда оно применяется?**
   Если классу нужен кастомный деструктор, конструктор копирования или оператор присваивания, то, скорее всего, нужны все три. Применяется, когда класс управляет ресурсами.

6. **Что такое «правило пяти»? Чем оно отличается от «правила трёх»?**
   Это правило трёх + конструктор перемещения и оператор перемещающего присваивания. Добавлено в C++11 для поддержки семантики перемещения (move semantics).

7. **В чём разница между конструктором копирования и оператором присваивания?**
   Конструктор создает новый объект на основе существующего. Оператор присваивания изменяет уже существующий объект.

8. **Зачем нужна проверка `if (this != &other)` в операторе присваивания?**
   Защита от самоприсваивания (`a = a`). Без нее можно случайно удалить собственные данные перед их копированием.

9. **Что такое итератор? Как он связан с указателем?**
   Это объект, позволяющий перебирать элементы контейнера. В простых контейнерах (как `Vector`) итератор часто является обычным указателем на элемент.

10. **Зачем нужны методы `begin()` и `end()`?**
    `begin()` возвращает итератор на первый элемент, `end()` — на элемент, следующий за последним (барьерный). Это нужно для циклов и STL-алгоритмов.

11. **Как реализовать range-based for для своего контейнера?**
    Нужно реализовать методы `begin()` и `end()`, возвращающие итераторы (или указатели), поддерживающие операции `*`, `++` и `!=`.

12. **Что такое «глубокое копирование»? Чем оно отличается от «поверхностного»?**
    Глубокое копирует сами данные (выделяет новую память). Поверхностное копирует только указатели, из-за чего два объекта начинают ссылаться на одну и ту же память.

13. **Что такое семантика перемещения и зачем она нужна?**
    Это механизм «перетаскивания» ресурсов из одного объекта в другой (с помощью `std::move`). Позволяет избежать дорогостоящего копирования.

14. **Почему конструктор перемещения помечается `noexcept`?**
    Чтобы контейнеры STL (например, `std::vector`) использовали перемещение вместо копирования при перевыделении памяти. Если перемещение может выбросить исключение, STL предпочтет копирование (для гарантии строгой безопасности исключений).

15. **Как правильно освобождать память в деструкторе?**
    Использовать `delete[]` для массивов, выделенных через `new[]`. В нашем случае с `std::shared_ptr` память освобождается автоматически, деструктор можно оставить по умолчанию (`= default`).
